# Terminal appearance: opacity, alpha, and applying the change

Terminal-level appearance (background translucency, fonts, colors) lives in the terminal's own
config, not in Hyprland. Read this before editing any `~/.config/<terminal>/` file. For the
Hyprland side of opacity (the `default-opacity` tag and its 0.985/0.96 rule) see SKILL.md,
"Opacity and blur".

## The stacking trap

A terminal's own background alpha does not replace the compositor's opacity, it multiplies with
it. Omarchy applies `opacity = "0.985 0.96"` to every window that still carries the
`+default-opacity` tag, and terminals are not opted out. So a request for "opacity 0.8" is
ambiguous: set the terminal alpha and the user gets ~0.79 focused / ~0.77 unfocused. Say so,
and offer either an app alpha or a window rule
(`o.window("foot", { tag = "-default-opacity", opacity = "0.8 0.8" })`) in
`~/.config/hypr/hyprland.lua`.

## Read the app's own config before writing to it

1. Find the user config and anything it includes. Omarchy themes are pulled in from
   `~/.local/state/omarchy/current/theme/<app>.*` via an `include=`, and those files are
   regenerated by `omarchy theme set` - so never edit them. Put the override in the user
   config: keys set later in the file win over whatever the include brought in.
2. Find the section an option belongs to in the installed version instead of guessing from
   memory or from another terminal. Terminals do not share key names or sections.
   - Sections of the man page: `man foot.ini | grep -n "^SECTION:"` (foot labels them
     `SECTION: <name>`), then read the section you need.
   - Shipped commented defaults show each key under its real section:
     `sed -n '1,140p' /etc/xdg/foot/foot.ini`.
3. Back up the file with a timestamp before editing:
   `cp ~/.config/foot/foot.ini ~/.config/foot/foot.ini.bak.$(date +%s)`.

### foot specifics (verified on 1.27)

- `alpha` (0.0-1.0 background translucency) and `alpha-mode` belong to
  `[colors-dark]` / `[colors-light]` - NOT `[main]` or `[colors]`. Misplacing them makes
  `foot --check-config` fail.
- `alpha` applies only to cells using the default background in `alpha-mode=default`; the
  other modes are `matching` and `all`. Leave the mode at the default unless the user wants
  colored cells translucent too.
- The default theme is `colors-dark` unless `initial-color-theme=light`; SIGUSR1/SIGUSR2 and
  the `color-theme-switch-*` bindings toggle between the two schemes. Setting alpha in only
  one scheme means the other one stays opaque.
- Verify without opening a window: `foot --check-config` (exit 0 = accepted, 1 = rejected).
  Unknown or misplaced keys fail it - run it after every foot edit.
- One-shot test of a single key without editing the file: `foot -o colors-dark.alpha=0.8`.

## Applying the change to running terminals

`omarchy restart terminal` reloads only alacritty (touch), kitty (SIGUSR1) and ghostty
(SIGUSR2) - read the script (`cat $(command -v omarchy-restart-terminal)`) rather than
assuming it covers the terminal in front of you. foot has no runtime config reload at all
(no reload binding, no config signal), so foot edits take effect in newly opened windows.

Report that plainly, then ask before closing or relaunching any of the user's terminal
windows: they may hold live shells or agent sessions, and a config change is never worth
killing one. Do not invent a signal or a `--reload` flag to make it apply live.
